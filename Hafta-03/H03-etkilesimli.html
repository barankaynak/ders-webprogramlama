A · Razor sözdizimi

Bir isteğin yolculuğu: @ nerede kayboluyor?

JavaScript tarayıcıda çalışır, Razor sunucuda. İkisi aynı dosyada yan yana yazılabilir ama farklı makinelerde, farklı zamanlarda çalışırlar — bu yüzden Razor’ı tarayıcının geliştirici konsolunda hata ayıklayamazsınız.
A · Kanıt

Söylemek yetmez — Ctrl+U ile bakalım

Soldaki yazdığımız dosya, sağdaki tarayıcıya gerçekten giden metin.

Views/Kitap/Index.cshtml
@model List<Kitap> <h1>Kitaplar</h1> <ul> @foreach (var k in Model) { <li><strong>@k.Baslik</strong> — @k.Fiyat TL</li> } </ul>
Üç pratik sonuç: ① Razor'ı tarayıcı konsolunda hata ayıklayamazsınız — orada yok.   ② Razor sunucunun kaynaklarına erişir (ama erişmemelidir — slayt 23).   ③ Kullanıcı tıklayınca Razor yeniden çalışmaz; yeni bir istek gerekir.
A · Sözdizimi

Ezberlenecek tek kural: @ = "buradan sonrası C#"

HTML kipi C# kipi Razor, ifadenin nerede bittiğini kendi anlar.

Açık ifade — parantez

@(kitap.Fiyat * 0.82m) TL @(kitap.Baslik)-indirimli.pdf

Parantez olmasaydı -indirimli.pdf C# sanılırdı.

Gerçek bir @ yazmak

<p>baran.kaynak@@ornek.edu.tr</p>

İki yorum — ikisi aynı değil

@* tarayıcıya HİÇ gitmez *@ <!-- kullanıcı Ctrl+U ile GÖRÜR -->

İç notu, "TODO"yu, parolayı asla HTML yorumuna yazmayın.

B · Layout

Menüye bir bağlantı eklemek kaç dosya açtırır?

Asıl tehlike unutmak değil, sessizce tutarsızlaşmak. Üç kopyadan birini güncellemeyi unutursanız uygulama hata vermez; yalnızca bir sayfada menü eksik kalır ve kimse aylarca fark etmez.
B · Layout · her sınavda çıkar

@RenderBody() sayfanın kendisi değil — içeriğin yerleşeceği yuva

Sıra çoğu kişinin beklediğinin tersidir: ① görünüm çalışır ② layout çalışır ③ görünümün çıktısı @RenderBody() yuvasına yerleşir. @section’ların çalışmasının sebebi budur — görünüm, parçasını layout’a önceden bırakır.

B · Layout seçimi

Bir projede birden fazla layout — ve hiç layout olmaması

Site layout’u

// _ViewStart.cshtml @{ Layout = "_Layout"; }

Varsayılan. Hiçbir şey yazmazsanız bu gelir.

Yönetim layout’u

// görünümün başında @{ Layout = "_AdminLayout"; }

Yalnızca o görünüm için. _ViewStart'ın değerini ezer.

Hiç layout yok

@{ Layout = null; }

Yazdırma sayfası, e-posta şablonu, bir parçayı tek başına döndürmek.

Layout'un da layout'u olabilir. _AdminLayout.cshtml kendi başında Layout = "_Layout"; diyerek site layout’unun içine yerleşir — katmanlı layout.
Layout veriyi nereden alır? Görünümün modelini bilmez, bilmemelidir. Ortak alan ViewData["Title"]'dır.
ViewData / ViewBag / TempData → Hafta 7. Daha sağlamı: View Component — Blok C.
C · Partial View

Layout sayfanın değişmeyen bölümünü paylaştırdı — peki ortasındaki tekrar?

kullanımı — Tag Helper yazımı
@foreach (var k in Model) { <partial name="_KitapKart" model="k" /> }
Kritik nokta: partial veriyi kendisi getirmez. Üst görünüm ne verirse onu basar.
model="k" yazmazsanız partial üst görünümün modelini alır — tip uyuşmazsa hata verir.

C · View Component

Peki parçanın kendi verisi varsa?

Sepet sayısı · "en çok okunan 5 kitap" · ziyaret sayacı — hiçbiri sayfanın modeliyle ilgili değil.

View Component bu sorunu çözer

Hem mantığı hem görünümü kendisi taşır. Yeni bir sayfaya koyduğunuzda o sayfanın controller'ında hiçbir şey yazmazsınız.

Bu, Hafta 2'nin "sessizce yanlış çalışma" temasının aynısı: unutmak hata vermez, yalnızca eksik çalışır.
