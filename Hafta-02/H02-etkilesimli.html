MVC deseni Y

Üç katman, üç soru

MVC, gelen isteği işleyen kodu üç sorumluluğa böler. Her katman tek bir soruyu cevaplar. Katmanlara tıklayın.

Controller'ın işi karar vermektir, iş yapmak değil. İdeal bir action üç satırdır: veriyi al, hazırla, döndür.

Sorumluluk ayrımı T

"Şişman controller" belirtisi

Bir controller metodu 50 satırı geçiyorsa, içinde muhtemelen başka katmanların işi vardır.

public IActionResult Detay(int id)
{
    var baglanti = new SqlConnection("Server=...");        // veri erişimi
    var kitap = baglanti.Query("SELECT * FROM Kitap...");   // veri erişimi
    if (kitap.Fiyat > 1000) kitap.Fiyat *= 0.9m;            // iş kuralı
    var html = "<h1>" + kitap.Baslik + "</h1>";             // HTML üretimi
    return Content(html);
}

Üç sorunu

  1. Test edilemez — veritabanı olmadan çalıştırılamaz
  2. Yeniden kullanılamaz — aynı kural başka yerde de gerekirse kopyalanır
  3. Nerede aranacağı belirsiz — bir şey bozulduğunda hangi katman?

Controller ve action Y

Action ne döndürür?

Sonuç HTML de olabilir, yönlendirme de, JSON da, dosya da. Bu yüzden dönüş tipi IActionResult — hepsinin ortak arayüzü. Sonuç tiplerine tıklayın.

Bir POST action'ının sonunda View() döndürmek kötü bir alışkanlıktır: kullanıcı sayfayı yenilerse form yeniden gönderilir ve ikinci kayıt oluşur. Doğrusu RedirectToAction — Post-Redirect-Get deseni, Hafta 4.

Route kısıtları

Bir segmentin tipini zorlayabilirsiniz. {id:int} → yalnızca sayı kabul eder; /Urun/Detay/abc artık bu route'a eşleşmez ve 404 alırsınız.

Attribute Routing

[Route("kitaplar")]
public IActionResult Index() => View();

[Route("kitap/{id:int}")]
public IActionResult Detay(int id) => View();

Sıranın ikinci tuzağı Y

Yetkilendirme yazdınız — ama dosya oraya hiç uğramıyor

Bir önceki bölümde sırayı bozduk ve hiçbir şey olmadı. Şimdi sıra doğruyken yine de sessizce açık kalan bir durum var. Bu, haftanın ilkesinin ikinci ve daha sinsi örneğidir.

app.MapStaticAssets();    // wwwroot içindekileri sun  → EŞLEŞİRSE KISA DEVRE
app.UseAuthentication();  // kim olduğunu belirle
app.UseAuthorization();   // yetkisi var mı bak

Bu davranış çoğu zaman istediğimizdir

CSS, logo ve yazı tipi dosyalarının yetki kontrolünden geçmesi gereksiz yavaşlık olurdu. wwwroot herkese açık olmak üzere tasarlanmıştır.

Tehlike, oraya ne koyduğunuzda

Kullanıcı faturalarını, yüklenen belgeleri veya yedekleri wwwroot altına koyarsanız adresi bilen herkes indirir. [Authorize] yazmış olmanız bir şey değiştirmez.

🧩 Haftanın ilkesi, ikinci kez: Program çalışmaya devam eder, hata vermez — yalnızca güvenlik varsayımınız sessizce yanlış olur. Hafta 14'te dosya yükleme yaparken bu tuzağa geri döneceğiz.

Mimari yapı Y

Dependency Injection ve yaşam döngüleri

Controller'ınız bir servise ihtiyaç duyuyor. En kolay yol new yazmaktır — ve üç sorun doğurur.

❌ new ile

var servis = new KitapServisi();
  1. Test edilemez
  2. Değiştirilemez
  3. Kaynak yönetimi elde değil

✅ Kurucu enjeksiyonu

// Program.cs
builder.Services
   .AddScoped<IKitapServisi, KitapServisi>();

// Controller
public KitapController(IKitapServisi s)
    => _servis = s;

Controller nereden geldiğini bilmiyor — ve bilmesi gerekmiyor.
